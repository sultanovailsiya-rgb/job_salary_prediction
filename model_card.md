# Model Card: модель предсказания годовой зарплаты

Описание составлено по шаблону Google Model Cards (Model Details, Intended Use, Factors, Metrics, Data, Analyses, Caveats).

## 1. Детали модели (Model Details)

| Параметр | Значение |
|---|---|
| Название | `final_pipeline` (Job Salary Prediction) |
| Тип | Регрессия: sklearn `Pipeline` = предобработка + `GradientBoostingRegressor` |
| Решаемая задача | Предсказание ожидаемой годовой зарплаты (USD) по характеристикам вакансии / кандидата |
| Разработчик | Коткова Ильсия, учебный проект по дисциплине «Автоматизация машинного обучения» |
| Версия / формат | 1.0, сериализованный пайплайн `models/final_pipeline.pkl` (joblib/pickle) |
| Зависимости | Python 3.11-3.13, scikit-learn 1.7.x (версия зафиксирована в `poetry.lock`; в другой версии pkl может не открыться) |
| Подбор параметров | Optuna (TPE, 20 trials, CV = 3) выбирает алгоритм из RandomForest / GradientBoosting / Ridge и его гиперпараметры. Лучший: GradientBoosting (`n_estimators=168`, `learning_rate=0.121`, `max_depth=6`) |
| Трекинг | MLflow (эксперимент `Job_Salary_Prediction`) |
| Воспроизводимость | `RANDOM_STATE = 42`, зависимости в `poetry.lock`, запуск `poetry run python -m src.main` |

## 2. Назначение (Intended Use)

- **Основная задача.** Быстрая оценка рыночной зарплаты для новой вакансии вместо ручного анализа рынка труда.
- **Целевые пользователи.** HR-менеджеры и рекрутеры, HR-аналитики и компенсационные менеджеры, руководители отделов (планирование ФОТ).
- **Допустимое использование.** Справочная оценка («вилка»-ориентир), сравнение предложений, черновое планирование бюджета.
- **Недопустимое использование.** Автоматическое принятие решений о зарплате конкретного человека без проверки специалистом; использование для данных, сильно отличающихся от обучающей выборки (другие страны, профессии, валюты).

## 3. Входные и выходные данные

**Вход** (одна запись, 9 признаков):

| Признак | Тип | Допустимые значения (в обучающих данных) |
|---|---|---|
| `job_title` | категориальный | 12 должностей |
| `experience_years` | число | 0–20 |
| `education_level` | категориальный | High School, Diploma, Bachelor, Master, PhD |
| `skills_count` | число | 1–19 |
| `industry` | категориальный | 10 отраслей |
| `company_size` | категориальный | Startup, Small, Medium, Large, Enterprise |
| `location` | категориальный | 10 локаций (USA, UK, Germany, India, Canada, Australia, Singapore, Sweden, Netherlands, Remote) |
| `remote_work` | категориальный | Yes, No, Hybrid |
| `certifications` | число | 0–5 |

**Предобработка внутри пайплайна:** `StandardScaler` для числовых признаков, `OneHotEncoder(handle_unknown='ignore')` для категориальных. Неизвестная категория не вызывает ошибку, но качество прогноза для неё не гарантируется.

**Выход:** одно число, предсказанная годовая зарплата в USD (`salary`).

## 4. Факторы (Factors)

Факторы, влияющие на качество и поведение модели:
- **Опыт работы** — самый сильный числовой предиктор (корреляция с зарплатой +0.43).
- **Должность, отрасль, размер компании, локация** — значимо влияют на результат (см. график важности признаков `results/plots`).
- **Группы с малым числом записей** (редкие сочетания должность/страна, зарплаты выше 99-го перцентиля) предсказываются хуже.
- Оценка качества по подгруппам (по странам, должностям) в проекте не проводилась.

## 5. Метрики (Metrics)

Метрики считаются на отложенной тестовой выборке (20 %):

| Метрика | Значение | Что означает |
|---|---|---|
| RMSE | ≈ $5 288 | типичная ошибка прогноза в долларах (сильнее штрафует крупные промахи) |
| MAE | считается в `main.py` | средняя абсолютная ошибка в долларах |
| R² | 0.978 | доля объяснённой дисперсии |
| MAPE | ≈ 3.1 % | средняя относительная ошибка |

Сравнение с базовыми моделями (из README):

| Модель | RMSE, $ | R² |
|---|---|---|
| Базлайн (медиана) | 35 948 | 0.00 |
| Ridge (alpha=1) | 6 842 | 0.964 |
| Random Forest (100 деревьев, глубина 12, без подбора) | 13 044 | 0.868 |
| **Gradient Boosting + Optuna** | **5 288** | **0.978** |

Основная метрика при подборе: RMSE на кросс-валидации. Для бизнеса понятнее MAPE (ошибка в процентах).

## 6. Обучающие и оценочные данные (Data)

- **Источник:** Kaggle, Job Salary Prediction Dataset (nalisha/job-salary-prediction-dataset), файл `data/job_salary_prediction_dataset.csv`.
- **Объём:** 250 000 записей, после очистки 247 500; 9 признаков + целевая переменная.
- **Очистка:** удаление пропусков, зарплат ≤ 0 и выбросов выше 99-го перцентиля.
- **Разбиение:** 80 % train / 20 % test (`random_state=42`); подбор гиперпараметров — кросс-валидация (3 фолда) только на train.
- **Особенности:** пропусков и дубликатов нет, данные выглядят синтетическими (очень чистые, высокий R²).

## 7. Количественный анализ (Quantitative Analyses)

- Gradient Boosting лучше всех: RMSE $5 288 против $6 842 у Ridge и $35 948 у медианного базлайна. Линейная модель тоже сильна (R² 0.964), то есть зависимость близка к линейной, а бустинг добавляет учёт нелинейных взаимодействий.
- Ошибка около 3 % от зарплаты при диапазоне зарплат ≈ $32 тыс. – $333 тыс. (после очистки верхняя граница ниже).
- Дрейф: функция `check_model_drift()` сравнивает MAPE с эталоном и сигнализирует при росте более чем на 20 %.

## 8. Этические аспекты (Ethical Considerations)

- Модель не использует пол, возраст, национальность. Однако `location` и `education_level` могут быть косвенными источниками неравенства: модель воспроизводит зарплатные различия, заложенные в данных, и не оценивает их справедливость.
- Нельзя использовать прогноз, чтобы занижать предложение конкретному кандидату.
- Персональных данных в датасете нет.

## 9. Ограничения и рекомендации (Caveats and Recommendations)

- Качество получено на одном датасете и одном разбиении; на реальных вакансиях (другой рынок, период, валюта) оно, вероятно, будет хуже. Высокий R² характерен для синтетических данных.
- Модель не учитывает инфляцию и время: данные статичны, без дат.
- Прогноз — точечное значение без доверительного интервала.
- Пайплайн привязан к версии scikit-learn (1.7.x).
- Мониторинг дрейфа в проекте учебный: эталон MAPE берётся с тестовой выборки того же запуска.
- Рекомендации: перед промышленным применением дообучить на реальных данных, добавить интервал прогноза, проверять качество по подгруппам и регулярно переобучать (см. `Model_retrain_BPMN.md`).
