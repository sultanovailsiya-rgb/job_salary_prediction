# Предсказание зарплат на основе машинного обучения
**Итоговый проект по дисциплине "Автоматизация машинного обучения". Коткова Ильсия, ИМО-2026**

## Описание бизнес-задачи
**Проблема**

HR-отделы и рекрутинговые агентства тратят большое количество времени на анализ рынка труда для оценки конкурентной зарплаты по новой вакансии. Ручной анализ приводит к субъективным оценкам, завышенным бюджетам на позиции, потере кандидатов из-за низких предложений и несоответствию зарплат рыночным реалиям.

**Решение**

Автоматизированная ML-система, которая предсказывает ожидаемую годовую зарплату, учитывая 9 ключевых факторов (опыт, навыки, образование, локация и др.) и обеспечивает точность.

**Бизнес-ценность**
- Сокращение времени оценки вакансии
- Повышение точности оценки
- Понижение вероятности ошибки

**Целевая аудитория**

HR-менеджеры и рекрутеры, HR-аналитики и компенсационные менеджеры, руководители отделов (например, при планировании ФОТ).

## Описание схемы пайплайна

1. Загрузка CSV

2. EDA и предобработка данных (очистка, кодирование, масштабирование)
    - Drop NA, фильтрация выбросов (99% квантиль)
    - StandardScaler (числовые признаки)
    - OneHotEncoder (категориальные признаки)

3. Выбор модели (RF, GB, Ridge) и подбор гиперпараметров (optuna)
    - Оптимизация гиперпараметров (20 trials)
    - Кросс-валидация (CV=3)

4. Обучение финальной модели
    - GradientBoostingRegressor
    - • n_estimators=200, lr=0.086, depth=7

5. Оценка на тесте (20% данных)
    - RMSE, MAE, R², MAPE
    - Логирование в MLflow

6. Сохранение пайплайна (Pickle)
    - Docker-контейнер
    - Готовность к продакшену

## Описание элементов ETL

**Extract (Извлечение)**

Источник данных: Kaggle — Job Salary Prediction Dataset https://www.kaggle.com/datasets/nalisha/job-salary-prediction-dataset

Характеристики: 250,000 записей (после очистки: 247,500), 10 колонок (9 features + 1 target), формат CSV

Категориальные признаки:
1) job_title - Название должности
2) education_level - Уровень образования
3) industry - Отрасль компании
4) company_size - Размер компании
5) location - Географическое расположение
6) remote_work - Формат работы

Числовые признаки:
1) experience_years - Опыт работы (лет)
2) skills_count - Количество навыков
3) certifications - Количество сертификатов
4) salary (целевая переменная) - Годовая зарплата ($)

**Transform (Преобразование)**

Очистка данных: удаление пропусков в целевой переменной (пропусков не обнаружено), фильтрация выбросов по зарплате (99-й перцентиль), удаление записей с неположительной зарплатой. Удалено 94 записи (0.04%) как экстремальные выбросы.

Предобработка признаков:
- Числовые признаки: StandardScaler (стандартизация, mean=0, std=1).
- Категориальные признаки: OneHotEncoder с обработкой неизвестных категорий (handle_unknown='ignore').

Все преобразования объединены в sklearn.pipeline.Pipeline.

**Load (Загрузка)**

Результаты пайплайна сохраняются в следующие артефакты:
- Модель: models/final_pipeline.pkl (сериализованный Pipeline)
- Метрики: results/metrics.json (RMSE, MAE, R², MAPE)
- Визуализации: results/plots/ (4 графика)
- Примеры предсказаний: results/sample_predictions.csv
- EDA-отчёт: results/eda_report.txt
- Логирование экспериментов выполняется через MLflow (параметры модели, метрики качества, важность признаков, графики обучения).

## Описание архитектуры ML-модели
Был выбран не готовый AutoML-фреймворк, а автоматизация отдельных частей - реализован модульный подход на базе Optuna (оптимизация гиперпараметров), Scikit-learn (ML-алгоритмы) и MLflow (трекинг экспериментов). В отдельных файлах лежат: EDA, тестыЮ мониторинг, модель и визуализация, которые вызываются с помощью функции main в файле "main.py".

Автоматизация реализована через:
- Автоматический выбор модели (Optuna перебирает 3 алгоритма и выбирает лучший)
- Автоматический подбор гиперпараметров (TPE-сэмплер находит оптимальные значения)
- Кросс-валидацию (3-fold CV для стабильной оценки качества)
- Автоматический трекинг (MLflow логирует все параметры и метрики)

**Алгоритмы-кандидаты**
1. RandomForestRegressor: ансамбль решающих деревьев, устойчив к переобучению. Параметры: n_estimators, max_depth, min_samples_split.
2. GradientBoostingRegressor (выбран как лучший): последовательное улучшение деревьев, высокая точность на табличных данных. Параметры: n_estimators, learning_rate, max_depth.
3. Ridge Regression: линейная модель с L2-регуляризацией, быстрое обучение. Параметр: alpha.

Целевая функция перебирает тип модели и гиперпараметры, оценивает качество через кросс-валидацию и минимизирует ошибку RMSE. Были запущены 20 итераций.
Результат оптимизации:
- Лучшая модель: GradientBoostingRegressor
- Лучший trial: 17
- CV RMSE: $5,291.87
- Оптимальные гиперпараметры:
    - n_estimators = 168
    - learning_rate = 0.121
    - max_depth = 6

## Полученные метрики модели

Сравнение моделей:
1. GB + Optuna
- RMSE $5,288
- R^2 0.978
2. Базлайн (медианная зарплата)
- RMSE $45,000
- R^2 0.000
3. Линейная регрессия (Ridge)
- RMSE $6,837
- R^2 0.654
4. Random Forest
- RMSE $5,424
- R^2 0.798

Вывод: Gradient Boosting с оптимизацией гиперпараметров показал наилучший результат, значительно превосходящий как простые базлайны, так и другие алгоритмы.

Анализ метрик:

RMSE = $5,288: при диапазоне зарплат $30,000 – $200,000 это отличная точность (ошибка ~2-4% от типичной зарплаты).

R² = 0.978: модель объясняет почти всю дисперсию данных. Это выдающийся результат для социально-экономического прогнозирования, указывающий на высокую предсказательную силу выбранных признаков.

MAPE = 3.1%: в среднем прогноз отклоняется всего на 3.1% от реальной зарплаты. Для HR-задач это более чем достаточно (обычно допустима погрешность ±15-20%).

## Запуск
Требуется Python 3.11-3.13 и [Poetry](https://python-poetry.org/).

```bash
poetry install                    # создаёт .venv и ставит зависимости из poetry.lock
poetry run python -m src.main     # EDA, подбор параметров Optuna, обучение, графики
poetry run pytest                 # тесты
poetry run pre-commit install     # включить хуки black, isort, flake8 перед коммитом
poetry run pre-commit run --all-files
```

Запуск в Docker:

```bash
docker build -t job-salary-prediction .
docker run --rm job-salary-prediction
```

**Почему виртуальное окружение не в Git.** Папка `.venv/` зависит от ОС и версии Python и занимает сотни мегабайт, поэтому она добавлена в `.gitignore`. Окружение полностью воспроизводится по `pyproject.toml` и `poetry.lock`, которые хранятся в репозитории.

## Тестирование
Автоматические тесты хранятся в "tests/test_model.py" и запускаются командой `poetry run pytest`:
- test_file_exists: проверка наличия датасета
- test_required_columns: проверка структуры данных
- test_salary_valid: валидация диапазона зарплат
- test_filters_target: проверка фильтрации целевой переменной в load_data
- test_create_model_ridge, test_build_pipeline_fit_predict, test_load_pipeline_missing_file: проверка сборки и загрузки пайплайна
- test_model_loads: проверка загрузки сохранённой модели

## Мониторинг
**Мониторинг качества модели** выполняется через MLflow. Отслеживаются метрики (RMSE, MAE, R², MAPE) на каждой итерации Optuna, важность признаков и параметры лучших моделей.

Реализована функция check_model_drift(), которая сравнивает текущий MAPE с базовым и сигнализирует при росте ошибки более чем на 20%. В текущем запуске:
- MAPE: 3.1%
- Коэффициент дрейфа: 1.00x
- Статус: Модель стабильна

**Мониторинг инфраструктуры** выполняется через Docker Stats. Загрузка CPU не превышает 70%, потребление памяти < 2 GB, время обучения ~30 минут (20 trials Optuna).
